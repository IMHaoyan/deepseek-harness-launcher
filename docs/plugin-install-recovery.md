# 插件安装中断后的恢复

安装依赖、将 bundle 加入 profile、以及运行时激活是三个不同阶段。

pnpm 可能先保存 dependencies 和 node_modules，再因尚未批准的安装脚本返回非零退出码。
DSH 的 CLI 只自动登记新加入的依赖，因此对残留依赖再次执行 add，可能成功退出但仍未加入
`dsh.profile.bundles`。DSHL 在明确的安装/重新安装、启用操作以及桌面登录辅助安装成功后，
现在会验证目标包身份与 bundle patch，并原子补齐该包的登记。清单扫描不会登记其他依赖，
补丁层和其他插件的禁用选择也不会被重置。

## 等待构建审批

如果提示 `ERR_PNPM_IGNORED_BUILDS`，请进入错误提示中的 web profile 目录，运行：

```powershell
pnpm approve-builds
```

检查列出的依赖，仅批准信任的安装脚本，再回到 DSHL 重试安装。例如手机连接插件可能引入
`@dataiku/uv`。不要为了消除提示而全局放开所有构建脚本，也不需要盲目升级/降级 pnpm。
启动器不会自动替用户批准脚本。

## 诊断与验证

- 失败的 CLI 输出会写入 DSHL 日志（单次最多保留 64 KiB），不只保留给界面展示的摘要。
- 明确区分等待构建审批与网络、版本门禁等错误；`UND_ERR_DESTROYED` 本身不能证明最初失败原因。
- 安装成功后仍需重启服务，查看是否有 bundle 被跳过或加载失败的日志。
- 桌面登录辅助登记成功后，启动日志应报告桌面壳与登录辅助就绪。真实账号授权需用户完成。

回归测试覆盖干净 profile 安装、失败后保留依赖的重试、桌面辅助 link 包修复、显式启用时修复，
以及不启用其他残留/禁用依赖。
